# دليل تشغيل عالي بيروت على خادم مستقل

هذه الحزمة هي الشفرة الكاملة للتطبيق بعد تحويله إلى تشغيل مستقل بواسطة Node.js وSQLite. يمكن رفع محتوياتها إلى مستودع GitHub خاص ثم تشغيلها على VPS باستخدام Docker. لا تحتاج إلى تسجيل الدخول بحساب ChatGPT.

## الفرق عن الأدلة المصورة المرفقة

أدلة المهندس والمدير والبائع داخل `docs/manuals` تشرح أقسام العمل. **تعليمات الدخول والاستضافة في هذا الملف تحل محل تعليمات حساب ChatGPT ومشاركة الموقع وأول إعداد داخل تلك الأدلة**:

- الإعداد الأول يتم من طرفية الخادم بأمر setup، وليس من صفحة عامة على الإنترنت.
- الدخول يكون ببريد الحساب المعين داخل التطبيق، ومستوى الوصول، وكلمة مرور المستوى.
- لا توجد مشاركة موقع منفصلة ولا حاجة إلى حساب ChatGPT.
- إضافة عضو من إعدادات النظام تكفي لإنشاء حساب مسموح له بالدخول؛ لا يرسل التطبيق رسالة بريدية.
- لكل مستوى كلمة مرور مشتركة، وفق تصميم النظام. معرفة كلمة المستوى وبريد حساب مسموح ضمنه تكفي للدخول بذلك الحساب؛ ليست هناك كلمة مرور مستقلة لكل مستخدم.

## محتويات الحزمة وحدودها

تتضمن الشفرة والواجهة وقاعدة البيانات المحلية عند إنشائها ومخزن الملفات وإعدادات Docker وHTTPS واختبارات GitHub والأدلة العربية.

**لا تحتوي الحزمة على بيانات الشركة الحية أو المستندات المرفوعة على الموقع السابق أو كلمات مروره.** يبدأ التشغيل بقاعدة فارغة، مع نموذج توضيحي منفصل للقراءة فقط. راجع MIGRATION.md إذا أردت نقل بيانات قديمة.

## تشغيل سريع على جهازك

ثبّت Docker Desktop على Windows أو Docker Engine مع إضافة Compose على Linux. فك الضغط، ثم افتح الطرفية داخل مجلد Aaly-Beirut.

على Windows PowerShell:

```powershell
Copy-Item .env.example .env
docker compose build
docker compose run --rm -it app node scripts/setup.mjs
docker compose up -d
```

على Linux استخدم `cp .env.example .env` بدلاً من أول أمر.

سيطلب الإعداد بريد المهندس وثلاث كلمات مرور مختلفة. اكتب كل كلمة وأعد تأكيدها؛ لا تظهر أثناء إدخالها. الطول من 10 إلى 200 حرف. لا توجد كلمات مرور افتراضية جاهزة.

افتح `http://localhost:3000` وسجّل الدخول:

| المستوى | بريد الحساب |
| --- | --- |
| المهندس | البريد الذي أدخلته أثناء الإعداد |
| المدير | manager@aaly.local |
| البائع | seller@aaly.local |

يمكن للمهندس إضافة حسابات الموظفين المسماة من إعدادات النظام. الحسابات الافتراضية معرفات محلية وليست صناديق بريد فعلية.

## النشر على VPS ودومين

1. انسخ المشروع إلى الخادم أو اسحبه من مستودعك الخاص.
2. وجّه سجل DNS للدومين إلى عنوان الخادم، وافتح منفذي 80 و443.
3. انسخ `.env.example` إلى `.env`، وعدّل `DOMAIN` إلى دومينك و`ACME_EMAIL` إلى بريد مسؤول الخادم.
4. نفّذ البناء والإعداد الأول كما سبق.
5. شغّل:

```sh
docker compose -f compose.yaml -f compose.https.yaml up -d --build
```

يتولى Caddy إصدار شهادة HTTPS وتجديدها. يفرض هذا الإعداد ملفات ارتباط آمنة ويضبط أصل الطلبات على الدومين نفسه. تحتاج هذه الخطوة إلى دومين وخادم متاحين فعلياً على الإنترنت.

إذا كنت تستخدم Nginx أو وكيل HTTPS آخر، شغّل compose.yaml فقط، واضبط `APP_ORIGIN` على رابط HTTPS الدقيق دون شرطة مائلة أخيرة، و`COOKIE_SECURE=true`، ثم وجّه الوكيل إلى `127.0.0.1:3000`.

هذا التصميم لخادم واحد ونسخة تطبيق واحدة مع قرص دائم. لا تشغّل عدة نسخ على ملف SQLite نفسه، ولا تستخدمه كموقع GitHub Pages أو على استضافة تحذف القرص عند إعادة التشغيل.

## الرفع إلى GitHub

أنشئ مستودعاً خاصاً فارغاً، ثم نفّذ داخل مجلد المشروع:

```sh
git init
git add .
git commit -m "Initial Aaly Beirut standalone application"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

استبدل عنوان المستودع بعنوانك الحقيقي. لا ترفع `.env` أو مجلدات البيانات والنسخ الاحتياطية. تستبعدها `.gitignore` تلقائياً. يجري GitHub اختبارات البناء؛ ولا ينشر تلقائياً على خادمك.

## النسخ الاحتياطي

أوقف التطبيق مؤقتاً حتى تكون قاعدة البيانات والملفات متطابقة زمنياً:

```sh
docker compose stop app
docker compose run --rm app node scripts/backup.mjs --app-stopped
docker compose start app
```

يطبع الأمر اسم مجلد النسخة داخل `/data/backups`. انسخه إلى خارج الحاوية بالاسم الدقيق:

```sh
docker compose cp app:/data/backups/EXACT-FOLDER ./aaly-backup
```

احتفظ بنسخة محمية على جهاز أو قرص آخر. تحتوي النسخة على البيانات والمستندات وتجزئات كلمات المرور. زر تصدير السجلات داخل التطبيق ليس بديلاً عن هذه النسخة الكاملة.

## الاستعادة إلى حجم تخزين جديد

أوقف التطبيق أولاً، ولا تحذف حجم التخزين القديم. أنشئ حجماً جديداً وانسخ إليه قاعدة النسخة ومجلد uploads. مثال Linux، من مجلد يحوي `aaly-backup`:

```sh
docker compose stop app
docker volume create aaly_restored
docker run --rm -v aaly_restored:/restore -v "$PWD/aaly-backup:/backup:ro" alpine sh -c 'cp /backup/aaly.sqlite /restore/ && if [ -d /backup/uploads ]; then cp -a /backup/uploads /restore/; fi && chown -R 1000:1000 /restore'
```

عدّل تعريف الحجم في نهاية compose.yaml ليشير إلى الحجم الجديد:

```yaml
volumes:
  aaly_data:
    external: true
    name: aaly_restored
```

ثم أعد تعيين كلمات المرور لإلغاء الجلسات القديمة، وأعد تشغيل التطبيق. لا تنسخ قاعدة النسخة فوق ملفات WAL أو SHM قديمة؛ استخدام حجم جديد يمنع ذلك. تحقق من سجلات عينة ومن تنزيل مستند قبل اعتماد الاستعادة.

## إعادة تعيين كلمات المرور

```sh
docker compose run --rm -it app node scripts/setup.mjs --reset-passwords
```

يتطلب هذا صلاحية دخول الخادم. يغيّر كلمات المستويات الثلاثة ويلغي الجلسات، ولا يحذف بيانات العمل.

## التحديث

خذ نسخة احتياطية، ثم اسحب التعديلات التي راجعتها من GitHub، وأعد تشغيل أمر النشر مع `--build`. تبقى البيانات في الحجم الدائم. لا تستخدم `docker compose down -v` إلا إذا أردت حذف البيانات نهائياً.

## التشغيل دون Docker

ثبّت Node.js 24 ثم نفّذ:

```sh
corepack enable
corepack pnpm install --frozen-lockfile
cp .env.example .env
npm run setup
npm run build
npm start
```

للخادم اضبط DATA_DIR إلى مسار دائم، واستخدم مدير عمليات ووكيل HTTPS. للاختبارات: `npm test` ثم `npm run build` ثم `npm run test:integration`.

## ما لا ينفذه الإصدار الحالي

قراءة الفواتير من الصور بالذكاء الاصطناعي غير متصلة. الفحص المصرفي يدقق الحقول المدخلة ووجود المستندات ولا ينفذ تحويلات مالية. لا توجد شاشة مرتجعات أو سلة متعددة المنتجات أو تحويل آلي من الخام إلى المطبوخ أو تذكيرات بريدية. هذه حدود النسخة الحالية وليست ميزات تعمل بمجرد نقلها إلى خادم.
